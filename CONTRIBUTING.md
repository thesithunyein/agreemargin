# Contributing to AgreeMargin

Open an issue for a workflow problem or proposed change. Explain who is affected and what they were trying to do. Use fictional project details in screenshots and reproduction steps. For a vulnerability, follow the [security policy](SECURITY.md).

1. Run the [local setup](README.md#local-development).
2. Keep the change focused. Preserve existing requests, review links, and manage links.
3. Run `npm run build` and `npm test`. For interface changes, check the affected flow with keyboard navigation and a narrow viewport.
4. Open a pull request with the user-facing change, verification results, and any deployment or migration requirements.

Use Sui Testnet for checkout testing. Follow the [Code of Conduct](CODE_OF_CONDUCT.md) when participating.
